# 售后替代料号查询

输入缺货的售后料号，查出可替代的其他售后料号。

## 这是什么

客服遇到售后料号缺货时，需要知道有没有其他料号可以替代发货。

本工具的做法：

```
售后料号 20020100006630（售后抹布架组件）
   ↓ 查 BOM 结构
下阶原材料 030300AA011600（抹布架组件）
   ↓ 查这个原材料被谁用到（使用情况）
   ✅ 20020100017362 售后抹布架组件-亚欧版   ← 可替代
   ❌ 20020100041577 售后左驱动轮组件         ← 共用原料但功能不同，排除
```

**关键点**：同一原材料会被几十个产品共用，所以光看"共用原材料"不够，还必须做**名称匹配**才能锁定真正可替代的料号。

## 架构说明

这个仓库只放**前端页面**（纯静态）。

因为查询需要登录公司内网的 PDM 系统抓数据，浏览器做不到，所以必须有一个后端服务运行在一台能访问内网的电脑上。

```
访客浏览器
    ↓
本页面（GitHub Pages 托管）
    ↓ 调 API
https://xxxx.ngrok-free.app（内网穿透，指向运行后端的电脑）
    ↓
后端服务 → PDM 系统
```

## 首次使用

页面打开后如果顶部提示"尚未配置后端服务"，点提示里的链接填入后端地址即可。

填入的地址会存在浏览器本地，下次打开不用重填。

也可以在网址后面加参数直接配置：

```
https://你的用户名.github.io/售后替代料号查询/?api=https://xxxx.ngrok-free.app
```

这个链接可以直接发给同事，他们打开就能用。

## 接口

后端提供以下接口：

| 接口 | 说明 |
|---|---|
| `GET /api/ping` | 健康检查，返回服务状态和缓存数量 |
| `GET /api/query?code=20020100006630` | 查询单个料号 |
| `GET /api/clear?code=xxx` | 清除单个料号的缓存 |
| `GET /api/clear` | 清除全部缓存 |

返回格式：

```json
{
  "input": "20020100006630",
  "inputName": "售后抹布架组件",
  "alternatives": [
    {
      "code": "20020100017362",
      "name": "售后抹布架组件-亚欧版",
      "sourceMaterial": "030300AA011600"
    }
  ],
  "unrelated": [
    { "code": "20020100041577", "name": "售后左驱动轮组件" }
  ],
  "level1": ["...BOM结构行..."],
  "level2": [{ "material": "030300AA011600", "rows": ["..."] }]
}
```

## 注意

- 查询首次约需 2 分钟（要打开 PDM 页面逐层读取），结果缓存 24 小时，重复查询秒回
- 后端电脑必须开机，关了服务就不可用
- 只支持 2001 / 2002 开头的售后料号
